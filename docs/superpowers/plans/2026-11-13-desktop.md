# Melly Desktop Implementation Plan

**Goal:** Build and verify a fast native Mac cloud-chat app with the approved design, safe provider boundaries, and a fully inspectable mock demo.

**Architecture:** Tauri uses the system WebKit view; Rust owns SQLite/FTS, provider HTTP, SSE parsing, cancellation, credential storage, OAuth and all tools. React is a thin rendering/input layer. Startup reads local bounded state and never awaits provider network.

**Tech stack:** Rust, Tauri2, React/TypeScript/Vite, rusqlite SQLite WAL/FTS5, reqwest/rustls, macOS Keychain.

## Global constraints
- Native Mac desktop app; launch speed, smooth streaming and responsive cancellation are defining features.
- Light and dark must preserve approved design, system font/regular weights/192px sidebar/768px transcript/quiet settings.
- Never fall back from a subscription endpoint to a metered endpoint. Never forward credentials across redirects or to search. Native secure key input; no secrets in frontend state, database, logs, fixtures.
- Folder scope derives from current chat in Rust. Search only other chats in same folder, snippets bounded, no automatic memory, untrusted reference text. No shell, coding tools, arbitrary URL fetch or private networks.
- ChatGPT official plan OAuth/Responses; other BYOK routes have no OAuth. The later Muse subscription request was investigated against the official host and SDK; Muse remains disabled for the concrete restrictions in docs/muse.md. Qwen Standard API and Token Plan separate endpoints/routes. Kimi general Moonshot API only.
- Mock flows explicit; no live claim without verification. User only has ChatGPT; sign-in can stay pending. No more routine approval gates.
- Requested empty-main commit already pushed after verified local snapshot; the later instruction authorizes feature-sized commits and checkpoint pushes directly to main, without a PR.
