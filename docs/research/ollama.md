[Message.tsx:858–869](https://github.com/ollama/ollama/blob/5632619189ab493c70bd3f9435214b8788cc1c80/app/ui/app/src/components/Message.tsx#L858-L869), [ChatForm.tsx:785–798](https://github.com/ollama/ollama/blob/5632619189ab493c70bd3f9435214b8788cc1c80/app/ui/app/src/components/ChatForm.tsx#L785-L798).

[Thinking.tsx:94–152](https://github.com/ollama/ollama/blob/5632619189ab493c70bd3f9435214b8788cc1c80/app/ui/app/src/components/Thinking.tsx#L94-L152), [Message.tsx:157–184](https://github.com/ollama/ollama/blob/5632619189ab493c70bd3f9435214b8788cc1c80/app/ui/app/src/components/Message.tsx#L157-L184).

## Web search

Search is a 36px globe control, neutral when off and blue when enabled; it is absent for unsupported models or disabled cloud. Its tooltip says Enable/Disable web search. Turning it on unauthenticated triggers a login prompt. [WebSearchButton.tsx:9–36](https://github.com/ollama/ollama/blob/5632619189ab493c70bd3f9435214b8788cc1c80/app/ui/app/src/components/WebSearchButton.tsx#L9-L36), [ChatForm.tsx:928–945](https://github.com/ollama/ollama/blob/5632619189ab493c70bd3f9435214b8788cc1c80/app/ui/app/src/components/ChatForm.tsx#L928-L945).

Transcript search activity is a muted inline row with small glyph and query text. Results collapse behind a row, with details disclosed on click. Browser-tool citations use small gray rounded inline number chips that link to source URLs and show the hostname on hover. The inspected implementation does not use a persistent sources side panel. [Message.tsx:136–248](https://github.com/ollama/ollama/blob/5632619189ab493c70bd3f9435214b8788cc1c80/app/ui/app/src/components/Message.tsx#L136-L248), [525–580](https://github.com/ollama/ollama/blob/5632619189ab493c70bd3f9435214b8788cc1c80/app/ui/app/src/components/Message.tsx#L525-L580), [StreamingMarkdownContent.tsx:239–284](https://github.com/ollama/ollama/blob/5632619189ab493c70bd3f9435214b8788cc1c80/app/ui/app/src/components/StreamingMarkdownContent.tsx#L239-L284).

## Translation for a new Mac cloud-chat app (design judgment)

Adopt the hierarchy: quiet native window → optional narrow history → readable centered transcript → one clear composer. Keep almost all controls in or immediately beside the composer. Use system type, restrained neutral fills, single-line history, contextual menus, and a few conventional glyphs. Blue should communicate an enabled capability, not decorate every surface. Give work status one muted transcript line and make sources inspectable inline.

For approval visuals, show an empty state and a real conversation state at a believable Mac-window scale. A new identity can be as small as a wordmark in an empty state; the llama, Ollama name, and their illustration style are unnecessary. Since this app is cloud-only, omit model downloads, local-memory controls, and local-vs-cloud badges. The model picker can still carry provider/model information. Persistent key/account setup belongs in settings; the chat view only needs a concise actionable state if credentials are missing.

Accessibility improvement for a new app: anything revealed by hover should also reveal on keyboard focus; icon toggles should have accessible names and pressed state. This is a recommended adaptation, not a claim about Ollama's present accessibility.

## Implementation and reuse boundary

The desktop application is a Go host with a React/Vite UI and native platform glue. It is not SwiftUI. The source README documents separate UI-dev and Go-app processes. [app/README.md:8–47](https://github.com/ollama/ollama/blob/5632619189ab493c70bd3f9435214b8788cc1c80/app/README.md#L8-L47). Reusing the whole application would also import local-runtime, model-management, authentication, native bridge, and storage assumptions; visual inspiration does not require that coupling.
